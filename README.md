# 職場ボトルネック診断アプリ

GSS（General Social Survey）2018・2022年の QWL モジュールから学習した2つのモデルを使い、
働き手のボトルネック（能力・余力・支援・機会）のうちどれを優先すべきかを判定する Streamlit アプリ。

このリポジトリにはアプリの実行に必要なファイルだけを置いている
（分析ノートブックと設計サマリーは手元の作業用リポジトリにあり、ここには含めていない）。

## モデル

| モデル                     | 役割                         | 指標                         |
| -------------------------- | ---------------------------- | ---------------------------- |
| 重回帰                     | 職務満足（1〜4）を数値で予測 | R² = 0.251                   |
| 分類（ロジスティック回帰） | 高満足かどうかを判定         | 正答率 69.1%（基準率 53.5%） |

説明変数は QWL 設問由来の4つ（`train` / `wrktime_r` / `suphelp_r` / `promteok_r`）。
アプリ側で再学習はせず、係数をそのまま使って「(回答 − 全回答者平均) × 係数」＝寄与度を計算し、
最もマイナスのカテゴリを優先ボトルネックとして提示する。

## モード

- **組織向け一覧（CSV一括）** — 多数の回答を読み込み、寄与度の低い順に介入先候補を並べる
- **QWL4問モード（1人）** — 本人の回答から1人ぶんを判定する
- **モデルの中身** — 係数一覧と、このアプリが主張できる範囲／できない範囲

## ローカル実行

```bash
pip install -r requirements.txt
streamlit run app.py
```

`gss_qwl.db`（学習データ、704KB）が同じフォルダに必要。
`sample_responses.csv` は組織向け一覧の動作確認用（回答はGSS実データ、氏名・所属はダミー）。

## Streamlit Community Cloud へのデプロイ

1. GitHub にリポジトリを作成し、このフォルダをプッシュする（`.gitignore` 済みの巨大ファイルは除外される）
2. https://share.streamlit.io にGitHubアカウントでサインインする
3. **New app** → リポジトリ・ブランチ・`app.py` を指定する
4. Advanced settings で Python 3.11 以上を選ぶ

必要なファイルは `app.py` / `gss_qwl.db` / `sample_responses.csv` / `requirements.txt` の4つ（合計約724KB）。

### デプロイ前の注意

**Community Cloud のアプリはURLを知っていれば誰でもアクセスできる**（非公開化は有料プラン）。
本アプリは氏名つきの職場評価、とくに上司への評価を扱うため、実在の社員データを投入する用途では
アクセス制御のあるホスト（Cloud Run + IAP、Render + Basic認証など）かローカル実行を推奨する。

アップロードしたCSVはアプリ側では保存されず、セッション中のメモリ上でのみ扱われるが、
通信先は第三者のサーバーである点に変わりはない。

## データについて

`gss_qwl.db` は GSS 1972–2024 累積ファイル（NORC が公開する公開利用ファイル）から
QWL関連の変数・2018/2022年ぶんを抽出したもの。
元ファイル `gss7224_r3a.sav`（3.8GB）は `.gitignore` で除外している。

## 判定の限界

- 集団平均の係数を使うため、個人ごとの効き方の違いは反映していない
- 相関にもとづく分析であり、因果関係は示せない
- ウェイト（`wtssps` / `wtssnrps`）を使っていないため、母集団水準の推定には使えない
